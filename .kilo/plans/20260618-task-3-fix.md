## Issues to Fix

### Issue 1: Component exceeds 200 lines (HIGH)

**Current**: `HowItWorksSection.vue` is 260 lines.  
**Cause**: Per-kind styles are duplicated (border, tag, line rules repeated for `empresa`, `cliente`, `sistema`, `resultado`).  
**Fix**: Adopt the `--node-color` custom-property pattern from the implementation plan. Consolidate common node/tag/line rules and only set `--node-color` per kind. Remove the redundant `.step-line-top`/`.step-line-bottom` structural elements in favor of a single pseudo-element rail on the steps container. This should bring the file well under 200 lines.

### Issue 2: Step 6 kind mismatch (MEDIUM)

**Current**: `{ kind: 'sistema', text: 'Los casos que requieren atención se revisan y confirman manualmente.' }`  
**Expected**: `{ kind: 'empresa', ... }` per `.kilo/plans/20260618-task-3-how-it-works.md` §5.2.  
**Fix**: Change step 6 `kind` to `'empresa'`. The label then becomes "Empresa", which matches the manual-review actor better than "Automático".

### Issue 3: Types shape drift (LOW)

**Current**: `HowItWorksStep` only has `kind` and `text`.  
**Expected**: `number`, `kind`, `icon`, `text` per plan §5.1.  
**Fix**: Add `number` and `icon` to the interface and use them in the component. Keeps the data model aligned with the plan and makes the component self-describing. If the refactor keeps the array index for numbering, `number` still documents the intended order.

### Issue 4: Semantic markup (LOW)

**Current**: Steps are plain `<div>` elements.  
**Recommended**: Use `<ol>`/`<li>` because the 7-step order is meaningful (matches the plan). Decorative number/icon should remain `aria-hidden`.
