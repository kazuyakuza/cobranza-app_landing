## Issue Found

### Issue 1: Favicon path regression in `index.html`

**Severity:** Medium — favicon will not load on GitHub Pages

**Description:**

The `base: '/cobranza-app_landing/'` configuration in `vite.config.ts` correctly transforms Vite-bundled asset URLs (scripts, stylesheets) in the build output. However, it does **not** transform static file references in `index.html` that use absolute paths starting with `/`.

**Current (broken):**
```html
<link rel="icon" href="/favicon.ico" />
```

This absolute path resolves to `https://kazuyakuza.github.io/favicon.ico` on GitHub Pages, which is incorrect. The file should resolve to `https://kazuyakuza.github.io/cobranza-app_landing/favicon.ico`.

**Evidence:** The built `dist/index.html` still shows `href="/favicon.ico"` — Vite did not apply the base prefix to this link.

**Secondary concern:** The `public/` directory is currently empty. No `favicon.ico` file exists. Even with the correct path, the favicon would 404 until the file is added.

## Fix

### Step 1 — Update `index.html` line 5

Change the favicon href to include the base path:

**Old:**
```html
    <link rel="icon" href="/favicon.ico" />
```

**New:**
```html
    <link rel="icon" href="/cobranza-app_landing/favicon.ico" />
```

This mirrors how Vite transforms the script src in the build output (`/cobranza-app_landing/assets/...`) and ensures the favicon resolves correctly on GitHub Pages.

### Step 2 — Verify build output

After the fix, rebuild with `npm run build` and confirm `dist/index.html` contains:
```html
<link rel="icon" href="/cobranza-app_landing/favicon.ico" />
```

### Step 3 — Commit

Commit with message: `fix: update favicon href to include GitHub Pages base path`

## Out of Scope

- Adding an actual `favicon.ico` file to `public/` (no file exists currently — separate task)
- This fix only addresses the path regression from the `base` configuration change
