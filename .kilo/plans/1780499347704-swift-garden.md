## Pre-Analysis

Four interrelated changes to improve mobile UX:

1. **Remove in-navbar mobile CTA** → free up navbar space
2. **Add floating bottom-right CTA** on mobile, hidden on hero/contact sections → visible where conversion matters
3. **Increase mobile padding** on hero (top) and footer (bottom) → prevent navbar/floating-btn overlap

Key architectural decision: The floating CTA is a standalone component (`FloatingCta.vue`) with its own IntersectionObserver tracking only `#hero` and `#contact`. This avoids lifting state to App.vue and keeps the change isolated.

### Change 1B: Auto-close menu on outside click
Add `onMounted` listener:
```typescript
function onDocumentClick(event: MouseEvent): void {
  const navElement = document.querySelector('.navbar')
  if (navElement && !navElement.contains(event.target as Node)) {
    closeNavCollapse()
  }
}

// In onMounted:
document.addEventListener('click', onDocumentClick)
```

### Change 1C: Auto-close menu on scroll
Add `onMounted` listener:
```typescript
function onWindowScroll(): void {
  closeNavCollapse()
}

// In onMounted:
window.addEventListener('scroll', onWindowScroll, { passive: true })
```

Cleanup in `onUnmounted`:
```typescript
document.removeEventListener('click', onDocumentClick)
window.removeEventListener('scroll', onWindowScroll)
```

## Task 2: Create FloatingCta.vue Component

**New File:** `src/components/landing/FloatingCta.vue`

### Component Design

```
<script setup lang="ts">
import { ref, onMounted, onUnmounted } from 'vue'
import { NAVBAR_HEIGHT_PX } from '@/utils/constants'

const isVisible = ref<boolean>(true)
let observer: IntersectionObserver | null = null

function scrollToContact(): void {
  const element = document.getElementById('contact')
  if (element) {
    const targetPosition = element.getBoundingClientRect().top + window.scrollY - NAVBAR_HEIGHT_PX
    window.scrollTo({ top: targetPosition, behavior: 'smooth' })
  }
}

onMounted(() => {
  const sectionsToHide = ['hero', 'contact']
  observer = new IntersectionObserver(
    (entries) => {
      for (const entry of entries) {
        if (entry.isIntersecting) {
          isVisible.value = false
          return
        }
      }
      isVisible.value = true
    },
    { rootMargin: '0px 0px 0px 0px', threshold: 0 }
  )

  for (const id of sectionsToHide) {
    const el = document.getElementById(id)
    if (el) observer.observe(el)
  }
})

onUnmounted(() => {
  observer?.disconnect()
})
</script>

<template>
  <Transition name="float-cta">
    <a
      v-show="isVisible"
      class="floating-cta d-lg-none btn btn-success fw-semibold shadow-lg"
      href="#"
      @click.prevent="scrollToContact"
    >
      Probar Beta Gratis
    </a>
  </Transition>
</template>

<style scoped>
.floating-cta {
  position: fixed;
  bottom: 1.25rem;
  right: 1.25rem;
  z-index: 1030;
  border-radius: 50px;
  padding: 0.75rem 1.5rem;
  font-size: 0.95rem;
  box-shadow: 0 4px 16px rgba(16, 185, 129, 0.4);
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

.floating-cta:hover {
  transform: translateY(-2px);
  box-shadow: 0 6px 24px rgba(16, 185, 129, 0.5);
}

/* Vue Transition classes */
.float-cta-enter-active,
.float-cta-leave-active {
  transition: opacity 0.3s ease, transform 0.3s ease;
}

.float-cta-enter-from,
.float-cta-leave-to {
  opacity: 0;
  transform: translateY(16px) scale(0.95);
}
</style>
```

### Edge Cases
- **IntersectionObserver behavior:** When hero OR contact is intersecting, hide. When NEITHER is intersecting, show. The `return` in the loop exits early on the first intersecting match.
- **rootMargin:** No margins needed — we want to hide as soon as any pixel of hero/contact is visible.
- **threshold: 0:** Trigger as soon as any pixel enters viewport.
- **Desktop:** Hidden via `d-lg-none` class, so `isVisible` reactivity is irrelevant at desktop.
- **z-index: 1030:** Below Bootstrap's `$zindex-fixed` (1030 for fixed navbar). But the floating button should be above content. Let's use 1030 — same as navbar, but at different position so no conflict. Actually, Bootstrap `fixed-top` uses `z-index: 1030`. We should use 1040 to be above cards but still reasonable. Or just match at 1030 since they don't overlap visually.
  - Decision: `z-index: 1040` to be intentionally above content cards that might use lower z-indices.

## Task 3: HeroSection + Footer Mobile Padding

### Change 3A: HeroSection.vue — Increase mobile top padding

**File:** `src/components/landing/HeroSection.vue`

The `.hero-section` currently has `padding-top: var(--navbar-height)` (70px). On mobile the title can be too close to the navbar.
